# Этап 7: стенд — план вечерней проверки

Для кого: пользователь и лид во время первой прошивки плат. Идём по шагам сверху вниз; каждый шаг проверяет одну вещь. Если шаг не прошёл — останавливаемся, лог монитора порта отправляем лиду.

Все команды — из корня проекта. Перед прошивкой лид спрашивает «какая плата подключена». Монитор порта: `pio device monitor -e <env>` (выход — Ctrl+C).

## Подготовка (без плат)
- [ ] `pio run -e rov_core -e buoy -e cam` — три SUCCESS.
- [ ] `pio test -e native` — все тесты PASSED.
- [ ] pyserial для утилит: `python3 -m venv .venv && .venv/bin/pip install pyserial "websockets>=13"`.
- [ ] Под рукой: 2× ESP32 (буй, ROV_CORE), ESP32-CAM с программатором (ESP32-CAM-MB или USB-UART), USB-UART адаптер 3.3 В (если есть), провода-перемычки, телефон.

## Шаг 1. Буй один (только USB)
1. Подключить ESP32 буя по USB.
2. `pio run -e buoy -t upload`, затем `pio run -e buoy -t uploadfs` (WebApp в LittleFS).
3. `pio device monitor -e buoy`. Нажать EN (reset) на плате.

**Ожидается в логе:**
```
[buoy] прошивка 0.1.0, протокол v2
[buoy] Wi-Fi AP "ROV_BUOY_AP", канал 6, IP 192.168.4.1
[buoy] LittleFS: отдаю /index.html
[buoy] HTTP :80 и WebSocket /ws запущены
```
и каждые 5 с две строки диагностики (клиенты, cmd/с, пакеты вниз/с, куча).

4. Телефон → Wi-Fi `ROV_BUOY_AP`, пароль `rov12345`. Если телефон спросит «сеть без интернета» — оставаться подключённым. Открыть в браузере `http://192.168.4.1`.

**Прошло, если:** WebApp открылся; в логе `WS: клиент #1 подключён`; в диагностике cmd/с ≈ 20; на экране «НЕТ СВЯЗИ» (телеметрии ещё нет — ТНПА не подключён) и ARM заблокирован. Это правильное поведение.

5. Свернуть браузер → в логе `WS: клиент … отключён (управлявший, команда сброшена)` или cmd/с падает до 0.
6. (Если есть USB-UART) режим `emulate-rov` из `tools/README.md` → «Стенд»: адаптер принимает пакеты буя, 20 Гц, на экране телефона появляется телеметрия, ARM разблокируется.

## Шаг 2. ROV_CORE один, без ESC и датчиков
1. Подключить ESP32 ROV_CORE по USB. **ESC не подключены.**
2. `pio run -e rov_core -t upload`, `pio device monitor -e rov_core`.

**Ожидается:**
```
[rov_core] прошивка 0.1.0, протокол v2. ESC = 1500 мкс, удержание 3000 мс
```
раз в 1 с: `пакетов/с=0 … armed=0 причина disarm: нет связи … M0=1500 M1=1500 M2=1500 M3=1500`, и строка `[датчики] MS5837=НЕТ … IMU=НЕТ …` (датчики не подключены — узел работает дальше). Встроенный LED медленно мигает (нет связи).

3. (Если есть USB-UART) `emulate-buoy` по сценариям `arm-sweep`, `failsafe`, `edge`, `badcrc` — что ожидать, печатает сама утилита.

## Шаг 3. Датчики на ROV_CORE (если есть GY-521 и MS5837)
Питание датчиков 3.3 В от ESP32, SDA → GPIO21, SCL → GPIO22, GND общий.

**Прошло, если:** в строке `[датчики]` MS5837=OK (после 2 с без «обнуление»), IMU=MPU6050 (или «клон»), после 2 с калибровки углы меняются при наклоне платы; depth ≈ 0.00 на столе; temp ≈ комнатной.
Проверка знаков IMU: наклон правым краем вниз → roll > 0; передним краем вверх → pitch > 0; поворот вправо (по часовой сверху) → yaw растёт. Если знак неверный — сообщить лиду (правится в `config.h`).

## Шаг 4. Буй ↔ ROV_CORE напрямую проводами (без RS-485)
На столе провода короткие, RS-485 не нужен. **Обе платы питаются от USB.**
```
Буй GPIO17 (TX) ──► ROV_CORE GPIO16 (RX)     управление
Буй GPIO16 (RX) ◄── ROV_CORE GPIO17 (TX)     телеметрия
Буй GND ─────────── ROV_CORE GND             обязательно
```
**Прошло, если:** на телефоне «СВЯЗЬ», телеметрия обновляется; в логе ROV_CORE пакетов/с ≈ 20, ошибок CRC = 0. ARM (удержание 1 с) → `[rov_core] ARMED`, движение джойстиков меняет мкс M0..M3 в логе по ICD §9 (surge вперёд → M0, M1 > 1500 и т.д.); DISARM → все 1500.
Fail-safe: выдернуть провод GPIO17 буя → в логе ROV_CORE `DISARM: нет связи` в пределах 0.5 с, все 1500; на телефоне «НЕТ СВЯЗИ» через ~1 с.

## Шаг 5. ESC и моторы — **ВИНТЫ СНЯТЫ**
Перед шагом лид отдельно спрашивает подтверждение «винты сняты». ESC должны быть перепрошиты в Bidirectional (`docs/esc_bidirectional.md`).
```
ESC0 сигнал → GPIO25 (корма левый)    ESC1 → GPIO26 (корма правый)
ESC2 сигнал → GPIO27 (нос вертикальный) ESC3 → GPIO13 (нос горизонтальный)
GND сигнальных разъёмов ESC → GND ROV_CORE.  Красный 5 В от ESC — НЕ подключать.
```
1. Сначала ESP32 (USB), потом батарея к ESC. ESC пищат и **не крутятся**.
2. ARM, затем по одной оси малым отклонением. Записать для каждого мотора: крутится ли, в какую сторону. Неверное направление → `MOTOR_DIR` в `config.h` (сообщить лиду).
3. Выдернуть провод управления (как в шаге 4) при вращении — моторы останавливаются за ≤ 0.5 с.

## Шаг 6. Камера
1. Прошить ESP32-CAM: `pio run -e cam -t upload` (на программаторе ESP32-CAM-MB — автоматически; на голом USB-UART — GPIO0 на GND при старте).
2. Монитор: строка `[cam] камера готова: …`, раз в 5 с `[cam] N к/с, ср. кадр … Б`.
3. Видео: ESP32-CAM GPIO13 → GPIO18 буя, GND общий. На телефоне появляется видео и счётчик к/с. Без буя — USB-UART + `tools/cam_rx.py` (см. `tools/README.md`).

## Что записать по итогам вечера
- какие шаги прошли/не прошли и логи непрошедших;
- направления моторов (шаг 5) и знаки IMU (шаг 3);
- к/с и средний размер кадра камеры;
- поле «loop макс» в логах ROV_CORE и буя.
