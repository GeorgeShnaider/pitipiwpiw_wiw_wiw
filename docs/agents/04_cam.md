# Субагент cam — Курсовая камера

**Исполнитель:** субагент `cam` (`.claude/agents/`), задачи ставит лид по этапам.
> Карточка для субагента прошивки камеры проекта ТНПА. Прочитай `CLAUDE.md`, `docs/agents/04_cam.md`, `docs/ICD.md` (§1, §2, §3, §7). Правишь только `src/cam/`.

## Владею
`src/cam/*`.

## Задача
ESP32-CAM AI-Thinker + OV2640, env `cam`. Wi-Fi **выключен** (`WiFi.mode(WIFI_OFF)`), Bluetooth тоже.

1. Инициализация `esp_camera` с пинами AI-Thinker (описать в `src/cam/camera_pins.h`), `PIXFORMAT_JPEG`, `CAM_FRAME_SIZE`, `CAM_JPEG_QUALITY`, `fb_count = 2`, `fb_location = CAMERA_FB_IN_PSRAM`, `grab_mode = CAMERA_GRAB_LATEST`.
2. Вспышка `CAM_FLASH_LED_PIN` всегда LOW.
3. UART1: TX `CAM_VIDEO_TX_PIN`, RX не используется, `VIDEO_BAUD`, увеличенный TX-буфер (`setTxBufferSize` до `begin`).
4. Цикл без `delay()`: если пора по `CAM_TARGET_FPS` и предыдущий кадр полностью отправлен, выполнить `esp_camera_fb_get` → заголовок (`seq++`, `length`, `videoHeaderSeal`) → JPEG → CRC16 → `esp_camera_fb_return`. Отправку вести порциями по свободному месту в TX-буфере (`availableForWrite`), чтобы не блокировать цикл.
5. Если кадр больше `VIDEO_MAX_FRAME`, не отправлять его и временно увеличить `quality` (автоподстройка в пределах 10..30).
6. Ошибка инициализации камеры: перезапуск камеры раз в 2 с, сообщение в лог.
7. Лог в USB Serial раз в 5 с: к/с, средний размер кадра, пропуски.

Если в процессе выяснится, что 921600 мало, можно подготовить замер и отправить `ЗАПРОС ЛИДУ` на `VIDEO_BAUD = 2000000`.

## Без буя
Подключить USB-UART (умеющий 921600, например CP2102/CH340) к GPIO13 и написать в отчёт Python-скрипт, который принимает поток, проверяет CRC и сохраняет кадры в .jpg.

## Готово, когда (финальная приёмка роли; лид может принимать по этапам)
- [ ] `pio run -e cam` без предупреждений.
- [ ] Скрипт на ПК сохраняет корректные JPEG, битых кадров меньше 1%.
- [ ] Замер: к/с и размер кадра при QVGA/q12 и VGA/q12.
- [ ] Отчёт лиду по шаблону из `CLAUDE.md`.
