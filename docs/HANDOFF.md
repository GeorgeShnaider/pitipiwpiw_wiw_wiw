Документ переносит в Claude Code всё, что обсуждалось в чате claude.ai при запуске проекта (23.10.2026). Лид читает его в начале **первой** сессии. ## 2. Что изменено относительно проектного предложения (с согласия пользователя)

| Было в предложении | Стало | Почему | Запись |
|---|---|---|---|
| Буй на ESP-01 (ESP8266) | Буй на ESP-WROOM-32 | У ESP-01 1 UART и ~40 КБ RAM: он не может принять телеметрию и видео одновременно и при этом держать Wi-Fi | D-001 |
| Кабель ССС-4G, 4 жилы | 8 жил, 4 витые пары (CAT5 нулевой плавучести) | Каждому потоку своя линия, без арбитража; контракт телеметрии не меняется | D-002 |
| UART TTL | UART поверх RS-485 | 10 м рядом с шестью ESC: TTL ненадёжен | D-003 |
| Видео: вариант А или Б | Вариант Б: JPEG по паре 4, новый контракт №4 | Вариант А требует отдельный коаксиал и гермоввод | D-004 |
| 2–4 маневровых | Пока ровно 2 в носу: вертикальный + горизонтальный | Решение пользователя; 4 маневровых — потом, если понадобится | D-005 |
| Подсветка: кто управляет — не решено | ROV_CORE (GPIO4 → MOSFET) | Команды приходят только на ROV_CORE | D-006 |

### Рассмотренные и отвергнутые варианты
- **Видео и телеметрия по одной линии с кадрированием.** На одном проводе оказываются два передатчика (ESP32 и камера). Тогда либо видео идёт через ROV_CORE (нарушает принцип разгрузки управления), либо телеметрия идёт через камеру (зависание камеры убивает телеметрию). Плюс пришлось бы менять контракт №3.
- **Видео по Wi-Fi камеры с выносной антенной в буе.** Отдельный коаксиал с потерями около 1 дБ/м, гермоввод, перепайка антенны на ESP32-CAM.
- **Питание буя 3.3/5 В по кабелю.** Просадка на 10 м тонкой жилы при пиках Wi-Fi до 500 мА вызовет перезагрузки. Поэтому подаём VBAT, а в буе ставим свой DC-DC (D-008).

## 3. Текущее состояние (на 23.10.2026, конец сессии в claude.ai)

- Репозиторий: `github.com/GeorgeShnaider/pitipiwpiw_wiw_wiw` (приватный), ветка `main`, первый коммит `8e23e41` — скелет.
- Скелет собирается на Mac пользователя: `pio run -e rov_core -e buoy -e cam` → все три **SUCCESS** (PlatformIO Core 6.2.0, `pio` добавлен в PATH).
- `src/*/main.cpp` — bring-up заготовки (баннер и мигание). Реального кода узлов ещё нет. `data/index.html` пустой.
- После первого коммита (ещё не закоммичено): раздел «Железо», процесс и шаблон отчёта в `CLAUDE.md`, этот файл, `docs/reference/`, новый `docs/agents/00_lead.md`, описания субагентов.
- **Описания субагентов лежат в `docs/agents/subagents/`**, потому что из claude.ai нельзя писать в `.claude/`. Первое действие лида: `mkdir -p .claude/agents && git mv docs/agents/subagents/*.md .claude/agents/` (или `mv`, если файлы ещё не в git). После этого перезапустить Claude Code, чтобы субагенты подхватились.
- Работа идёт в ветке `dev` (создать от `main`: `git checkout -b dev`).
- Пользователь создал worktree `../rov-wt-core` (`feat/rov-core`) и `../rov-wt-webapp` (`feat/webapp`). С переходом на субагентов они **не нужны**: пользователю предложено удалить их (`git worktree remove …`, `git branch -D …`).

## 4. Открытые вопросы по железу (выяснить у команды, не блокируют код)

1. **Зарядка.** В бюджете указан модуль заряда **3S 12.6 В**, а батарея **4S 16.8 В**. Он не зарядит батарею полностью. Нужен заряд 4S с балансировкой или внешнее зарядное.
2. **Делитель VBAT.** В `config.h` заложено 100 кОм / 22 кОм. Нужно узнать реальные номиналы и откалибровать `VBAT_CAL_K` по мультиметру.
3. **Что докупить:** кабель 8 жил нулевой плавучести (10 м), RS-485-трансиверы 3.3 В (2× MAX3490/3491 для пар 2–3, 2× MAX3485 для пары 4), терминаторы 120 Ом, понижающий DC-DC в буй (вход до 17 В, выход 5 В), предохранитель 1 А, N-MOSFET для LED-ленты, второй ESP32 для буя.
4. **ESC.** Все 6 нужно перепрошить в **Bidirectional** через BLHeliSuite. Без этого реверса нет.
5. **Провод подсветки** от отсека 4 к отсеку 5 идёт через отсек 2: учесть в разводке.
6. **IMU:** какой именно модуль куплен (MPU6050 или MPU6500).
7. **Носовые маневровые смещены от центра масс:** heave даёт дифферент, sway — рыскание. Компенсацию подбирать коэффициентами `MIX` на испытаниях. В предложении у аналога «Alen» вертикальный движитель стоит у центра масс именно ради этого.

## 5. Как пользователь хочет работать

- Язык общения, комментариев и документации — **русский**.
- **Коммиты — только с явного разрешения**, в конце сессии. Перед коммитом показать сводку изменений и предложить сообщение.
- Контракты №1–4 менять только с согласия пользователя.
- Пользователь хочет, чтобы лид сам раздавал задачи субагентам, сам проверял и принимал работу и приходил к нему только за решениями.
- Объяснения — по делу, с вариантами и рекомендацией, когда есть выбор.

## 6. Ближайшие шаги для лида

1. Прочитать `CLAUDE.md`, `docs/agents/00_lead.md`, `docs/ICD.md`, `docs/decisions.md`.
2. Попросить у пользователя разрешение закоммитить файлы передачи (см. §3).
3. Параллельно запустить субагентов `rov-core` (этап 1: ESC + fail-safe + разбор ControlPacket) и `webapp` (UI + `tools/mock_buoy.py`).
4. Затем `buoy` (WebSocket ↔ UART без видео), после него `cam` и видеоветку буя.
5. Передать команде список вопросов по железу из §4.
