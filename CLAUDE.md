# ТНПА с надводным буем: правила для всех агентов

Этот файл читает **каждый** агент в начале сессии. Затем он читает свою ролевую карточку в `docs/agents/` и `docs/ICD.md`.

## Проект

Мелководный ТНПА (до 5 м), которым управляют с телефона. Три прошивки в одном PlatformIO-проекте и автономный WebApp:

| env | Узел | Плата | Каталог |
|---|---|---|---|
| `rov_core` | Главный контроллер (отсек 4) | ESP-WROOM-32 | `src/rov_core/` |
| `buoy` | Надводный буй (узел 6) | ESP-WROOM-32 | `src/buoy/` + `data/` |
| `cam` | Курсовая камера (отсек 5) | ESP32-CAM OV2640 | `src/cam/` |

Архитектура, кабель, пины и все протоколы описаны в **`docs/ICD.md`**. Причины решений записаны в `docs/decisions.md`.

## Владение файлами

У каждого файла **один** владелец. Чужие файлы не правятся, даже ради одной строки.

| Владелец | Файлы |
|---|---|
| Лид (чат 0) | `platformio.ini`, `include/*`, `docs/*`, `CLAUDE.md`, `.gitignore` |
| WebApp (чат 1) | `data/index.html`, `tools/mock_buoy.py`, `tools/README.md` |
| Буй (чат 2) | `src/buoy/*` |
| Бортовой контроллер (чат 3) | `src/rov_core/*` |
| Камера (чат 4) | `src/cam/*` |

Если нужно изменить чужой файл, контракт, пин или константу, агент **не правит сам**. Он пишет запрос лиду в формате:

```
ЗАПРОС ЛИДУ: <файл> — <что изменить> — <зачем> — <на кого влияет>
```

Пользователь переносит запрос в чат лида.

## Неприкосновенные контракты

Контракты №1–4 (JSON-ключи WebSocket, `ControlPacket`, JSON-телеметрия, видеокадр) описаны в `docs/ICD.md` и `include/protocol.h`. Менять их можно **только** через лида и **только** с согласия пользователя.

## Правила кода

1. **Никаких блокирующих вызовов** в `loop()`, коллбэках и задачах управления: без `delay()`, без ожидания в `while`. Используются только таймеры на `millis()`/`micros()` и конечные автоматы. `delay()` допустим лишь в `setup()` до запуска управления.
2. **Без кучи в рабочем цикле:** в `loop()` и сетевых коллбэках нельзя использовать `String`, конкатенацию, `new`/`malloc`. Только статические `char[]`, `snprintf`, структуры. ArduinoJson — только `JsonDocument` на стеке/статике с ограниченным размером, разбор из буфера.
3. **Fail-safe важнее всего.** Таблица уровней защиты — в ICD §8. Нет валидных пакетов > 500 мс означает, что все ESC получают 1500 мкс.
4. **Константы только из `config.h`/`protocol.h`.** Никаких «магических» пинов и чисел в коде узлов.
5. **Полный компилируемый код.** Нельзя оставлять `// TODO`, `// ...`, заглушки и закомментированные куски.
6. Сборка без ошибок и **без предупреждений** (`-Wall -Wextra`).
7. Платформа: Arduino-ESP32 **core 2.0.x** (`espressif32 @ 6.9.0`). API 3.x (`ledcAttach` и т.п.) не используем.
8. Комментарии и сообщения в логах на русском, идентификаторы на английском.

## Рабочий процесс

- Каждый агент работает в своей ветке: `feat/webapp`, `feat/buoy`, `feat/rov-core`, `feat/cam`.
- Перед изменением файла его нужно прочитать. Файлы перезаписываются целиком только при необходимости.
- В конце сессии агент проверяет сборку `pio run -e <свой env>` и пишет **отчёт для лида**: что сделано, что проверено, какие отклонения от ICD и какие запросы есть.
- Коммиты делаются **только с разрешения пользователя**. Сообщение коммита: `<узел>: <что сделано>`.
- В `main` сливает только лид после ревью (чек-лист в `docs/agents/00_lead.md`).
